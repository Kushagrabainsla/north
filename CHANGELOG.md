### Performance & Reliability (6 Fundamental Architectural Fixes)
- **Reactive Slot-Based Batch Scheduling & Drain Queue** (`jobs/scheduler.py`, `jobs/sqlite_processor.py`):
  - Replaced single-item candidate searching in `CronScheduler` with batch slot matching across all due entries, preventing same-minute cron starvation and 24-hour skips.
  - Added reactive `_wake_event` signalling and batch queue draining in `SQLiteJobProcessor`, draining queued bursts in milliseconds rather than sleeping 5 seconds per job.
- **Dual-Tier Event Bus & Turn-Gated Streaming Buffer** (`inference/providers/openai_compat.py`, `orchestrator/stream.py`):
  - Increased SSE subscriber queue capacity to 2048 and added priority eviction for non-token lifecycle events (`task_completed`, `agent_completed`) to guarantee they are never dropped under high-frequency token generation.
  - Added stream reset invocation on tool call detection, ensuring pre-tool reasoning fragments are not leaked into the user-facing output stream.
- **Pooled WAL Persistence, Schema Migration Guards & Atomic Pagination** (`ledger/sqlite_writer.py`, `memory/consolidator.py`, `utils/db.py`):
  - Guarded FTS5 table rebuilds to only run if the FTS index is empty and existing ledger rows need indexing, eliminating multi-second startup latencies and exclusive locks.
  - Standardized `EpisodeConsolidator` on $+1\,\mu\text{s}$ pagination and atomic file writes (`tempfile` + `os.replace`).
- **Non-Blocking Subprocess & Early-Pruned I/O Engine** (`context/code_index.py`, `tools/universal/search_files.py`, `context/lsp_client.py`):
  - Offloaded `CodeIndex` file scanning, reads, and SHA256 computations to `asyncio.to_thread`, keeping the async event loop completely unblocked.
  - Replaced `Path.rglob()` with top-down `os.walk(topdown=True)` in `SearchFilesTool` to prune `node_modules`, `.venv`, and `.git` at the root directory level.
  - Added process exit checks in `lsp_client.py` (`self._proc.poll() is not None`) to fail fast with `LspError` immediately upon server crash rather than busy-waiting for 20 seconds.
- **Optimistic CAS File Locking & Granular Mutation Concurrency** (`tools/specialized/patch_file.py`, `orchestrator/task_context.py`):
  - Added Compare-And-Swap (CAS) validation in `PatchFileTool._write` that verifies the file on disk matches the planned content before writing, aborting with conflict errors if modified during user approval waits.
  - Reduced `TaskContextStore.read()` fallback poll interval from 10.0s to 0.25s.
- **Unified Task Lifecycle Manager & Terminal State Contract** (`orchestrator/orchestrator.py`, `orchestrator/failure_handler.py`, `gateways/telegram.py`):
  - Centralized task cleanup in `Orchestrator._process_task`'s `finally:` block to purge `PlanStore`, `FailureHandler`, `CostTracker`, and `RunningTaskStore` memory on every exit path.
  - Added `clear_all(task_id)` to `FailureHandler`.
  - Updated `TelegramGateway._get_task_result` to prioritize terminal records (`task_synthesis`, `task_completed`) over intermediate agent logs.

### Fixed
- **Home agent prompt no longer contradicts the kasa tool's contract** (`agents/home/prompts/system.md`) — the prompt told the agent `device` was optional and to "omit it to affect all discovered bulbs", with examples like `"turn off the lights" → action=off, no device`. But the kasa tool was since hardened to **require** an explicit device for every control action (an omitted device must never fan out to every bulb) and rejects a device-less control call - so the agent would follow its prompt, omit the device, and the tool would error. Rewrote the guidance and every example to target a named device (list first, then act per device), matching the tool, and broadened "bulbs and switches" to what kasa actually controls (plugs, switches, bulbs, light strips). **Live-verified**: "list my smart home devices" routes to `home`, calls kasa `list`, and returns the discovered device.
- **Streaming answers no longer re-render when they finish** (`cli/tui.py`, `tests/unit/cli/test_tui.py`) — the live token stream rendered through Textual's `Markdown` widget while the finalized message rendered through **rich's** `Markdown` in the log, so tables and headings subtly re-flowed/changed chrome at the hand-off (a long-standing `TODO(tier-2)`). The live stream now renders the growing buffer through the **same** rich `Markdown` engine (a `Static` updated with `RichMarkdown`, left-indented by CSS to match the final message's `RichPadding`), so the message simply moves from the capped live area into the scrollback with no visual change. Removes the dead Textual-Markdown-block CSS and the unused import; a regression test asserts the live widget's renderable is a `rich.markdown.Markdown` and that the live area hides on completion. **957 pass**, ruff clean.
- **Two TUI UX bugs, found by a headless runtime probe and now regression-tested** (`cli/tui.py`, `tests/unit/cli/test_tui.py` - the TUI had **no tests** before) — driving `NorthApp` through Textual's `run_test()` Pilot surfaced two real defects: **(1) paste desync** - a large paste is stashed and shown as a `[pasted: N lines …]` placeholder, but if the user then edited the line to a *different* message, pressing Enter still sent the **stale paste**, not what they saw (input and action diverged). Now the paste is sent only if the placeholder is untouched; any edit (typing, history, editor) sends the visible text and discards the paste. **(2) Focus trap** - Tab on an empty prompt moved focus onto the read-only chat log (a focusable `RichLog`), after which keystrokes went nowhere and nothing returned focus. The chat log and live-stream panes are now `can_focus = False`, so Tab or a click can never strand the input (mouse-wheel scrolling still works). Six new tests cover both fixes plus a full SSE-lifecycle smoke test and a narrow-terminal status-bar render; **956 pass**, ruff clean.
- **Research/writing tasks no longer misroute to the engineering pipeline** (`prompts/planner.md`, `agents/coder/config.yaml`, `agents/researcher/config.yaml`, `agents/reviewer/config.yaml`) — a live audit found that a literature review ("write a literature review on LLM inference serving") and "find an open-source issue to contribute to" both classified as `engineering` and were sent down the researcher→architect→coder→reviewer pipeline (slow, irrelevant skills, no clean deliverable). Root cause: the weak planner matched **generic verbs in the engineering agents' `accepts` lists** (`coder: write`, `researcher: research/analyze/find`, `reviewer: review` — which even matched "literature *review*") over the prose guidance. Fixed by (1) leading the planner's domain step with a prominent **code-gate** that explicitly says not to classify a task as engineering on a verb like research/write/review/find/analyze alone; (2) pruning those generic verbs from the engineering agents' `accepts` (`review` → `code review`); and (3) a guardrail that the engineering agents run **only inside the engineering pipeline** — a general research/writing task is handled by the `general` agent (which can web-search and write the deliverable). **Validated live**: the literature-review prompt now routes `general` → `general` agent and produced an accurate **11.6 KB** report; "find an OSS issue" → `general`; and code tasks (implement / fix / code-review / add-tests) still → `engineering`.
- **`north start` now launches a truly detached background server** (`cli/_server.py`, `cli/main.py`) — the server subprocess was spawned in the CLI's own session/process group, so closing the terminal sent it SIGHUP and killed it (and with it every background job: the cron scheduler, job processor, memory extraction, and episode consolidation). It now starts in its own session via a cross-platform `_detached_process_kwargs()` helper (POSIX `start_new_session`; Windows `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`), so `north start --no-chat` stays up after the terminal closes and keeps all scheduled/background work running. Verified: the launched server is its own session leader (survives terminal close), boots healthy, and runs the in-process scheduler. Stop it with `north stop`.

### Added
- **No more em/en dashes in north's writing (the "AI tell"), enforced in code** (`prompts/soul.md`, `utils/text.py`, `agents/agentic_llm_agent.py`, `tools/universal/write_file.py`) — north's output was littered with `—`/`–` (an old report carried **16 em + 5 en dashes**), the classic giveaway of machine-written text. Fixed with the same two-layer pattern north uses for safety: **(1)** a global voice rule in `soul.md` (injected into every agent) telling north to write with commas/colons/parentheses/hyphens instead, and **(2)** a deterministic `normalize_dashes()` filter that *guarantees* it regardless of the weak model - because a prompt rule alone leaks on free-tier models. The filter runs at north's output boundaries: the final message content, the **live SSE token stream** (so interactive chat is clean as it types, not just the stored copy), and the `write_file` tool. Em dashes/horizontal bars become a spaced hyphen (` - `) with inline spacing collapsed; en dashes become a plain hyphen in place (`3–5` → `3-5`); **hyphen-minus is untouched**, so markdown `---` frontmatter, `-` bullets, and existing hyphens survive, and **newlines are never crossed** so list/line structure is preserved. Crucially, `write_file` **only normalizes prose** (`.md`, `.txt`, docs, unknown types) and **never code/data files** (`.py`, `.json`, `.csv`, `.yaml`, …), because a dash there may be a literal, test-verified byte - silently rewriting a string literal the coder already verified would be a correctness bug. 10 new unit tests (dash cases, newline safety, markdown structure, the code/data carve-out); **950 pass**, ruff clean. **Validated live**: a conversational reply (1,281 chars) and a written report file (1,930 chars) both came back with **0** em/en dashes while their plain hyphens stayed intact.
- **`conducting-a-literature-review` skill + general-domain skills enabled** (`skills/builtin/conducting-a-literature-review/SKILL.md`, `agents/base.py`, `skills/models.py`, `skills/README.md`) — north's first **non-engineering** skill, giving the `general` assistant a rigorous, grounded method for the research/literature-review tasks that route to it (per the routing fix above, knowledge-synthesis with no codebase → `general`, not the code-first engineering researcher). This **completes the deferred step** from the skill domain-eligibility entry below: `general` is added to `_SKILLS_ENABLED_DOMAINS`, and because `_load_skills_block` filters by `Skill.domains`, the assistant only ever sees skills tagged `general` (this one) while engineering skills never leak into ordinary chat — and vice versa (guarded by `test_research_skill_serves_general_not_engineering`). The skill's method is distilled from the best open-source deep-research systems — **GPT Researcher** (query decomposition, source curation, inline-citation mandate, "form a concrete opinion"), **STORM** (sub-question framing, outline-then-write, "do not hallucinate"), **dzhng/deep-research** (learning extraction with entities/metrics/dates, iterate on follow-ups), **OpenDeepResearcher** (relevance screening, convergence/stop), and **PRISMA-lite** (frame → systematic multi-source search → screen → synthesize → gaps). **Validated live, and it caught a real backfire:** the first version *selected* correctly but the weak model treated the numbered procedure as an output template — it echoed the step names as headings ("Query Frame / Gather Broadly / Screening") and wrote an ungrounded review from memory with **zero `web_search` calls**. Rewritten to (1) make searching **non-negotiable** ("a review from memory is a failed task"), (2) give a concrete **report template** to pattern-match against instead of the procedure, and (3) forbid narrating the process; and its **description was tightened** to exclude personal writing. Re-test on the same prompt: `tools_used = [web_search, fetch_url, write_file]`, **12 real sources opened**, a 15.8 KB report with **55 inline citations**, clean thematic sections + Trade-offs/Conclusion/References, and no process-narration — while a cover-letter prompt that had spuriously selected the skill (noise) now selects nothing. **940 tests pass.**
- **Universal stop: cancel any task or job, or everything at once** (`orchestrator/orchestrator.py`, `orchestrator/api_router.py`, `cli/main.py`) — `north cancel <id>` stops whatever the id refers to (the **server** resolves active-task vs pending/running-job, so you don't need to know which), and `north cancel --all` stops everything in flight (all active tasks + all pending/scheduled jobs). Backed by `Orchestrator.cancel_all_tasks()` and two endpoints — `POST /orchestrator/cancel/{id}` and `POST /orchestrator/cancel-all`. A *running* scheduled (cron) job is just an active task/job, so this stops it too; stopping *future* recurrences is `north stop` (halts the scheduler). **Verified live**: cancel-by-id returned `{cancelled: task}`, cancel-all stopped 2 in-flight tasks, all confirmed by `task_cancelled` ledger entries.
- **Skill domain-eligibility: the foundation for skills beyond engineering** (`skills/models.py`, `skills/registry.py`, `skills/selector.py`, `agents/base.py`) — a skill now declares which agent domains it serves via a `domains:` frontmatter list (default `[engineering]`, matching every shipped skill), exposed as `Skill.domains` + `Skill.available_to(domain)`; `_load_skills_block` filters candidate skills to those eligible for the acting agent's domain, and `SkillSelector.select` accepts that candidate subset. This is the mechanism that lets skills safely serve any domain (each agent only ever sees domain-appropriate skills). **Actually enabling non-engineering domains was deliberately deferred** after a live experiment: with only engineering skills present, ungating the general assistant made a single eligible skill match essentially everything — an unrelated "how do I stay productive?" prompt scored **0.55-0.63** against the OSS-scouting skill, and the *same* prompt varied run-to-run (0.547 → 0.633) — so no absolute similarity threshold can reliably gate one general skill on today's compressed embeddings. Reliable general selection needs *several distinctive per-domain skills* (chosen by relative ranking, not an absolute floor), which arrives with the domain-specialist consolidation. Net behaviour today is unchanged (engineering-only); the tested mechanism is in place for that next step.
- **"Policy": a fourth capability primitive for authoritative, always-on rules** (`agents/policy.py`, `policies/`, `docs/ARCHITECTURE.md` §2.1) — north now has a named, principled taxonomy: **tool** (deterministic code), **skill** (advisory procedural *knowledge*, semantically selected, injected low, never overrides), **policy** (an authoritative *rule*, activated deterministically by agent, injected high in the system prompt, binding), and **agent** (a separate execution boundary — justified only by a different model / context isolation / unique tools / a distinct mission, *not* a mere persona). Policies live as `policies/*.md` files with `applies_to: "*"` (every agent) or a list, loaded once at import and rendered into the system-prompt tier by matching agent name. Loading **fails closed** — a missing/empty directory or any malformed/empty policy raises `PolicyError` at import, so a typo can never silently drop the guardrails (the design flaw a rubber-duck flagged as the biggest risk). Two policies ship: **`safety.md`** (all agents) consolidates rules that were copy-pasted, with wording drift, across **10 of 11 agent prompts** — report tool failures honestly (never claim success on `success:false`), never fabricate facts/figures/prices/citations (label estimates as estimates), and confirm before irreversible/external actions (scoped so it doesn't fight the coder's routine workspace edits, and *not* downgraded in autonomous mode for destructive actions); and **`clean-code.md`** (coder+reviewer) — the existing clean-code rules, migrated from the bespoke `_CLEAN_CODE_POLICY` constant into the one mechanism (content unchanged, tests green). The redundant generic `success:false` rule was **deduped** from the finance/health/job/university prompts (domain-specific triggers kept local). Policies are the instruction layer, explicitly backed by deterministic enforcement where it exists (approval-gated mutating tools, the Definition-of-Done gate). 13 new tests; **933 pass**; live-smoke confirmed the server boots with fail-closed loading and a task completes normally.
- **Graceful model scarcity: north runs with whatever model access it has, without lowering its rigor** (`orchestrator/failure_handler.py`, `orchestrator/orchestrator.py`) — when the whole model pool is rate-limited or a provider quota is dead, north now degrades on *availability* instead of changing its behaviour. Three fixes, all rubber-ducked against weak-model backfire and covered by 12 tests: (1) **honest classification** — `AllModelsRateLimitedError`/`PaymentRequiredError` were silently tagged `logic_error` (as if north had a *bug*) and retried 3× into the same wall; they now classify as a dedicated `model_unavailable` (walking the `__cause__`/`__context__` chain so a *wrapped* scarcity error is still caught) and are non-retryable (the dispatcher already walked the pool). (2) **Honest terminal outcome** — a task blocked solely by scarcity ends as a distinct `task_skipped_model_unavailable` action that `get_task` reports as status **`skipped`** ("model pool exhausted - retry when model access recovers"), not a generic `task_failed`, so "ran out of models" reads differently from "north got it wrong"; stored as `FAILED` so retention/consolidation/extraction treat it correctly with no new enum. (3) **A non-critical step's scarcity no longer sinks the task** — if the coder finishes but the independent reviewer can't get any model, north completes the task (the deterministic tests/lint DoD gate still runs) with an honest "review skipped: model pool exhausted" note instead of failing work that is already done. Failures now carry their `error_type` structurally (a `str`-subclass `AgentFailure`, zero-ripple at every existing call site) so the skip/fail decision is deterministic — **a real bug is never mislabelled as a graceful skip** (any non-model failure forces `task_failed`). The eval harness (`evals/harness.py`) now recognises the new `skipped` status and counts it as a non-graded infra outcome (excluded from the pass rate, like error/timeout) rather than grading unwritten code. Live-smoke confirmed no regression on the happy path.
- **Coder guardrails from the Devin/Claude Code system prompts, made always-on** (`agents/coder/prompts/system.md`, `prompts/soul.md`) — three sharp rules the best coding agents rely on: **don't change a test just to make a failure disappear** (fix the code; strengthen tests, never weaken them), **don't assume a new third-party library is available** (check imports/manifest first; adding one is a deliberate dependency change), and **don't create unsolicited artifacts** (new source/test/config files are fine, but no README/docs/scripts unless asked). A global scope line in `soul.md` ("deliver the requested outcome completely… but don't add unrequested scope, files, refactors, or features") stops gold-plating without discouraging implied verification. Each rule was **rubber-ducked for weak-model backfire** and reworded to lead with the real constraint (block cheating/hallucinated-deps/clutter) while explicitly permitting legitimate test and new-file work. **Live-validated**: with the rules, a failing-test bugfix fixed the *code* (`/10`→`/100`) and *added* a discriminating regression assertion instead of cheating; a control run (no rules, on weak `llama-4-scout`) behaved the same, confirming the rules are non-harmful insurance rather than a regression; and a task needing a new module created exactly `tax.py`+`test_tax.py` with no refusal and no unsolicited docs — so rule 3 doesn't backfire. The coder's self-contradictory `## Ask, never assume` heading (its body already said "decide and proceed") was renamed to match.

- **Orchestrator-run verification oracle in the Definition-of-Done** (`orchestrator/orchestrator.py`, `orchestrator/dod.py`, `config/settings.py`, `orchestrator/app.py`) — after a conductor coding task, the orchestrator now runs the project's tests *itself* and feeds the exit code into the DoD, so "done" rests on an executable oracle rather than the model's (or the reviewer's) word. The reviewer prompt now instructs honest reporting (never claim red→green or a regression test you didn't see), and the conductor coder is told to leave the reproduction behind as a lasting regression test.

(4) **Planner code-vs-no-code hardening**: explicit read-only-verb vs change-verb cues so "is there a bug in X?" / "how does Y work?" route to `question`/`research` and only a clear request to change code routes to `bugfix`/`refactor`/`feature`. Purely prompt changes — no code paths touched; all 793 tests still pass.
- **The engineering conductor is now the default, with an enforcing Definition-of-Done gate** (`config/settings.py`, `orchestrator/orchestrator.py`) — step 6 of the engineering-loop redesign: `engineering_conductor_enabled` now defaults to **on**, so engineering tasks run as the continuous coder + orchestrator-driven different-model reviewer + bounded fix loop by default. The DoD gate is no longer warn-only on this path: a task whose recorded evidence does not clear the bar (a code change was applied, the structured review passed, and it ran on a *different model* than the coder) now finishes as `task_completed_with_failures` with the specific reasons recorded in the ledger and surfaced in the streamed answer - so a coding task is never reported as a clean success it did not earn. It is non-blocking (partial work is preserved and delivered, with a clear "not fully done" note), and fails open (a gate error never breaks the task). The classic `researcher→architect→coder→reviewer` pipeline + prose-regex QA loop remain as a fallback (`NORTH_ENGINEERING_CONDUCTOR_ENABLED=0`) and will be removed in a follow-up once the conductor is validated on real tasks.
- **Curated preferred models per pool + per-task model stickiness** (`inference/model_policy.py`, `inference/dispatcher.py`, `config/strategy.py`): the dispatcher used to rank the whole provider catalog purely by price (`quality_from_cost`), then *shuffle* among near-equal-priced models - so a coding task was handled by "the priciest model that happens to be up," and the model could change between ReAct steps. Now a small, ordered, editable list of known-strong models is *preferred* per pool (`reasoning`, `fast_cheap`): the available, healthy preferred models are tried first in curated order, with the price-ranked catalog kept as a resilient fallback (a stale or unavailable preference never blocks a call - it degrades to the old behaviour and logs why). Preferred entries are **family-matched** against the live catalog (`anthropic/claude-sonnet` matches `anthropic/claude-3.7-sonnet`, `…-sonnet-4`, …), survive version bumps, and can be provider-qualified (`groq:llama-3.3`). A preferred model that keeps failing is **health-gated** (dropped back to its price position after enough failures) so it can't pin errors/latency to the front. Configurable via `~/.north/settings.json` (`preferred_models`) or the `NORTH_PREFERRED_MODELS` env var; empty falls back to the built-in `DEFAULT_PREFERRED_MODELS`. Startup + every pool refresh warn when a preferred id matches nothing in the live catalog. Separately, the **first model that succeeds for a `(task_id, component, capability, priority)` is reused for that task's later steps** (bounded LRU, emits a "model switched" log on change), so a multi-step coding task is completed by one consistent model instead of re-rolling each call - the property that actually matches Claude Code / Cursor / opencode. `ECO`/`SPORT`/`CRUISE` strategy semantics are unchanged.
- **Approval mode: one dial for how much north does without asking** (`approval/mode.py`, `approval/unattended.py`, `approval/approval_memory.py`, `approval/judgement_filter.py`): a single `NORTH_APPROVAL_MODE` setting with three ordered tiers, replacing the older `unattended_mode`/`autonomous_mode` booleans (still honoured as a fallback):
  - **`interactive`** (default) - read-only actions run freely; every mutating action asks. No auto-resolution, no learning.
  - **`auto`** - additionally auto-approves a deterministic SAFE subset (editing files inside the task workspace, an allowlist of test/lint/build commands, and local git add/commit/branch/checkout/stash); **and it learns** - for anything outside that subset it replays the user's own prior decision (recorded per action fingerprint in `ApprovalMemory`), or asks and remembers the answer, so `auto` needs the human less over time.
  - **`autonomous`** - approves *everything*; the mode is the only authority. There is no approval-level floor and no learned-rejection replay, and the tools' own hard refusals (`bash` blocking `rm -rf /` / fork bombs / `dd` / `> /dev/sd*`; `git` blocking force-push) are lifted in this mode. Genuine `ask_user` questions are still never auto-answered - only permission cards.
  Auto-resolution runs through the JudgementFilter (the single auto-decision chokepoint), so it covers every gated tool uniformly.
- **LSP integration + `rename_symbol` refactor** (`context/lsp_client.py`, `tools/specialized/rename_symbol.py`) (#1, #4): a minimal, robust Language Server Protocol client (stdio JSON-RPC, verified against pyright) gives engineering agents *semantically accurate* code intelligence. The coder-only `rename_symbol` tool renames a function/class/method/variable and every reference to it across the workspace via the language server's own WorkspaceEdit - scope-aware and safe, never touching same-named symbols in other scopes, comments, or strings (the one refactor grep-and-replace can't do safely). Python is supported when `pyright-langserver` is installed; other languages are a lookup-table away, and everything fails soft to a clear "do a targeted edit" message. The reviewer deliberately does NOT get this tool (it never edits code).
- **`search_code` semantic code search + `CodeIndex`** (`tools/semantic/search_code.py`, `context/code_index.py`): "search by meaning" over the workspace (#2 code RAG) - a natural-language query returns the most semantically related functions/methods with file paths and line ranges, so the coder can locate relevant code without knowing the identifier to grep for. Symbol-aware chunking (Python AST per function/method/class-card; overlapping line windows for other languages), incremental re-embedding by per-file content hash, batched embeddings, and cosine retrieval - reusing north's existing embedding infrastructure (embed_fn, cosine, SQLite). Fails soft to an empty result (caller falls back to grep/search_symbols) when no embedding model is available.
- **`lint` universal tool** (`tools/analysis/lint.py`): runs the project's own linter/formatter (ruff for Python, eslint for JS/TS, gofmt for Go) with structured, line-level findings; `fix=true` auto-fixes and formats in place. Auto-discovered for every agent and wired into the coder's per-file verify step and the evidence gate. ESLint output is parsed via `--format json` (the `unix` formatter was removed from ESLint 9 core).
- **`update_plan` tool + task-scoped plan store** (`tools/universal/update_plan.py`, `orchestrator/plan_store.py`): agents maintain a live checklist (the "TodoWrite" pattern) - decompose a task into ordered steps and flip each `pending → in_progress → done`. The current plan is streamed to the UI (`plan_updated` event) and injected back into agent context so a long or resumed task stays anchored on progress.

### Changed
- **Approval mode is now a live setting** (`config/strategy.py`, `orchestrator/api_router.py`): `approval_mode` is persisted in `~/.north/settings.json` (like `strategy`) and read at decision time, so `GET`/`POST /orchestrator/settings` switches it at runtime with no restart. `NORTH_APPROVAL_MODE` (and the legacy booleans) set the startup default; a value in settings.json overrides it. - **Inference: empty / instruction-ignoring model responses now fall through** (`inference/dispatcher.py`): a model that returns a 200 OK but an empty completion - or, for a `json_mode` request, prose / a `<thought>` trace instead of JSON - is now treated as a *failure* rather than a success, so the dispatcher deprioritises it (brief cooldown) and tries the next candidate. Previously one broken model at the top of the pool (e.g. a free model that ignores `json_mode`) silently broke every JSON caller - the planner, judgement filter, and extraction - making tasks stall or no-op. This makes routing resilient to a large, mixed-quality model pool.
- **Planner failure is now honest, not a silent no-op** (`orchestrator/router.py`): the intent planner retries a transient inference failure (each attempt time-bounded so a hung model can't stall the task), and if every attempt fails it raises `RoutingError` so the task is marked FAILED and can be retried - instead of silently degrading to a general single-agent run that reports "completed" having done nothing.
- **Task status reflects real progress, not the latest step** (`orchestrator/orchestrator.py`): `get_task` now reports a task's status from its most recent *terminal* ledger entry (completed / failed / cancelled), not the single most recent entry. Intermediate steps (classification, each agent) are logged COMPLETED per-step, so a still-running task was reporting "completed" the instant it was classified; it now correctly reports "pending" until the work is actually finished and persisted.
- **Honest completion status for denied/failed edits** (`orchestrator/orchestrator.py`): the engineering evidence gate now also flags a run that *attempted* a code edit (`patch_file`/`write_file` in `tools_used`) which never succeeded (absent from `successful_tools`) - e.g. an approval was denied - so a coder can no longer claim "done" when no change was applied. The violation routes through self-repair and, if unresolved, annotates the answer instead of reporting a clean success.
- **Sandboxed execution for the bash tool** (`tools/specialized/_sandbox.py`, `tools/specialized/bash.py`) (#6): with `sandbox_enabled` (default off), approved shell commands run inside a Docker container that only sees the workspace (bind-mounted at `/workspace`), with the network off and memory/CPU/PID limits plus `no-new-privileges` - defense in depth so even an approved command can't reach the rest of the host or the internet. It **fails closed**: when sandboxing is requested but Docker is unavailable (or no workspace is mounted), the command is refused rather than silently run on the host. Configurable image and resource limits via settings; `sandbox_enabled=false` leaves host execution unchanged.
- **Best-of-N coder attempts** (`orchestrator/best_of_n.py`, `orchestrator/orchestrator.py`, `orchestrator/worktree.py`) (#11): with `best_of_n > 1` (default 1 = off), the orchestrator runs several independent coder attempts in parallel isolated git worktrees and integrates only the best one, discarding the rest. Candidates are ranked deterministically - viable (ran and changed something) first, then tests-passing (via an optional `best_of_n_test_command` scored by exit code), then the smallest diff, then lowest index. Costs N× the coder's inference, so it is opt-in for high-stakes changes; N=1 leaves today's single-worktree path untouched.
- **CI-awareness + PR lifecycle** (`tools/specialized/gh_tool.py`, coder/reviewer prompts) (#8, #13): the `gh` tool gains `pr_status` (read-only) and `pr_ready` (approval-gated), and its description now points agents at `pr_checks` (read a PR's CI status) and `run_view --log-failed` (fetch failing CI logs). The coder learns a PR/CI workflow - open or update a PR (approval-gated), then treat a red CI check like a failing review: fetch the failing logs, fix the cause, re-check until green. The reviewer gains read-only `gh` access and now folds remote CI status into its report (a red CI is a FAIL). `pr_merge` is never called by an agent.
- **`tester` agent broadened into `reviewer`** (`agents/reviewer/`): the QA specialist is now the engineering quality gate - it runs the tests AND reviews the coder's diff for bugs, edge cases, security, and quality, then reports a prioritized MUST-FIX / NICE-TO-HAVE fix-list back to the coder. Promoted from the `fast_cheap` to the `reasoning` model pool (it must reason about code as well as the coder). The deterministic engineering chain, coder↔reviewer QA loop, planner, and all teammate prompts now reference `reviewer`; a registry alias (`tester → reviewer`) keeps legacy delegations working.
